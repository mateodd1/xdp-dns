⚙️ 3. Detalle Explicativo de los Servicios

Caddy Web & TLS caddy.service

Termina TLS con certificados Wildcard de Let's Encrypt para *.xdp.es. Sirve DoH sobre HTTP/2 y HTTP/3 (QUIC) en el puerto 443 y hace proxy reverso a Blocky.

dnsproxy (DoQ) xdp-doq-dot.service

Implementación RFC 9250 para DNS over QUIC sobre UDP 853. Cero bloqueo de cabeza de línea (*Head-of-Line*) y migración fluida de redes (Wi-Fi ⇄ Datos móviles).

Blocky Adblock & Lite blocky.service

Servidor en Go que gestiona el filtrado. Si un dominio es publicidad o malware, responde con 0.0.0.0 al instante. También sirve DoT nativo en TCP 853.

evade-proxy (Rust) xdp-evade-proxy.service

Proxy intermedio de altísimo rendimiento en Rust (Tokio). Revisa si las IPs devueltas por Unbound sufren bloqueos de fútbol y las sustituye en memoria en tiempo récord.

Unbound Recursivo unbound.service

Resolver recursivo autoritativo. Hace la consulta directa a los servidores raíz del mundo, valida firmas DNSSEC y oculta la consulta completa con QNAME Minimisation.

dnsleak-gate dnsleak-gate.service

Observador efímero en memoria para la zona _check.xdp.es (puerto 53 en IP .54). Alimenta el test web de /test para verificar si el usuario navega por XDP.

🛡️ 4. Cómo Funciona el Cambio de IPs (Evasión Cloudflare)

El problema de los bloqueos deportivos: Durante partidos de fútbol, se ordena a las operadoras españolas bloquear IPs Anycast de Cloudflare donde emiten webs piratas. Al ser Anycast, se tumban también miles de páginas web inocentes.

El algoritmo de evasión de evade-proxy:

  • 1. Consulta BGP ultrarrápida: Carga 348 prefijos IPv4 y 68 prefijos IPv6 de Cloudflare (AS13335). Comprueba por búsqueda binaria $O(\log N)$ si la IP pertenece a Cloudflare.
  • 2. Detección de Bloqueo: Compara con la lista negra sincronizada en tiempo real (/etc/unbound/blocked_ips.txt).
  • 3. Sustitución Anycast: Busca una IP contigua en la misma subred (ej: cambia 104.21.45.10 por 104.21.45.11). Como Cloudflare responde por cabecera Host:/SNI en todas las IPs de su nodo, la web carga perfectamente.
  • 4. TTL Cero: Ajusta el TTL = 0 para que el navegador no guarde en caché la IP modificada.
  • 5. Proveedores no-Cloudflare: Si la IP es de Google, AWS, OVH, Hetzner, etc., no se modifica.

📊 5. Motor de Estadísticas y Métricas (update-stats.py)

Garantía Zero-Logs + Estadísticas Reales: El servidor no almacena historiales de navegación ni qué dominios consulta cada usuario. Solo mantiene contadores numéricos agregados en memoria RAM (formato Prometheus) que se consolidan cada 30 segundos.

El script update-stats.py se ejecuta periódicamente mediante update-stats.timer y sigue este flujo:

[Blocky Adblock :4000] [Blocky Lite :4002] [evade-proxy :5339] │ │ │ └────────────────┬───────┴─────────────────────┘ │ ▼ 1. RECOLECCIÓN EN MEMORIA RAM (Suma los contadores numéricos de todos los servicios) │ ▼ 2. CÁLCULO DE VENTANAS MÓVILES (Rolling Deltas) (Calcula qué ha pasado en las últimas 24h y 30 días usando history.json) │ ▼ 3. RESOLUCIÓN ANÓNIMA DE OPERADORES (Team Cymru) (Consulta DNS inversa para identificar el ASN sin guardar la IP) │ ▼ 4. CLASIFICACIÓN INTELIGENTE (ISP vs Datacenter) (Separa conexiones de hogares reales de servidores/bots) │ ▼ 5. PUBLICACIÓN ATÓMICA DE stats.json (/var/www/xdp.es/stats.json -> Servido a la web en vivo)

Detalle de cada fase del motor:

  • 1. Recolección en RAM: Lee las métricas de Prometheus en 127.0.0.1:4000/metrics (Adblock), 127.0.0.1:4002/metrics (Lite) y 127.0.0.1:5339/stats (consultas de fútbol evadidas).
  • 2. Ventanas móviles (24h y 30 días): Como los contadores en RAM vuelven a cero si se reinicia un servicio, el script guarda snapshots en history.json. Si detecta un reinicio, compensa el salto para no perder el histórico ni duplicar conteos.
  • 3. Identificación anónima vía Team Cymru: Para saber qué operadoras usan el DNS sin almacenar IPs de personas, consulta a *.origin.asn.cymru.com. Las respuestas se guardan en asn_cache.json con un TTL de 7 días para evitar saturación de consultas.
  • 4. Clasificación (ISP Residencial vs Datacenter): Discrimina automáticamente entre operadores residenciales (Movistar, Vodafone, Orange, DIGI, MásMóvil, Starlink, Avatel, etc.) y datacenters/hosting (OVH, Hetzner, AWS, Cloudflare, Ginernet). Así, la gráfica pública solo refleja el reparto de usuarios reales.
  • 5. Publicación atómica: Escribe en un fichero temporal y realiza un os.replace hacia /var/www/xdp.es/stats.json, garantizando que el navegador nunca lea un JSON corrupto a medio escribir.

⏰ 6. Automatizaciones y Temporizadores Systemd

Dos timers del sistema mantienen la infraestructura actualizada de forma 100% desatendida:

  • update-blocked-ips.timer (Cada 1 minuto): Descarga las IPs bloqueadas desde hayahora.futbol. Si hay cambios, actualiza los archivos locales, vacía automáticamente las cachés de Blocky (blocky cache flush) y Unbound (unbound-control flush_zone .) y refresca el panel interno /blocked.
  • update-stats.timer (Cada 30 segundos): Ejecuta update-stats.py para recolectar métricas en RAM, clasificar ASNs y generar el archivo stats.json que alimenta /stats y la home.

💻 8. Guía Rápida de Comandos y Mantenimiento

Comprobar estado de todos los servicios:

systemctl status caddy blocky blocky-lite blocky-ota xdp-evade-proxy unbound unbound-lite xdp-doq-dot xdp-lite-doq dnsleak-gate

Reiniciar toda la infraestructura:

systemctl restart caddy blocky blocky-lite blocky-ota xdp-evade-proxy unbound unbound-lite xdp-doq-dot xdp-lite-doq

Purgado manual de cachés:

# Purgar caché de filtrado Blocky blocky cache flush --apiPort 4000 blocky cache flush --apiPort 4002 # Purgar caché recursiva de Unbound unbound-control -c /etc/unbound/unbound.conf flush_zone . unbound-control -c /etc/unbound/unbound-lite.conf flush_zone .

Comprobación de resolución DoH (HTTP/3):

curl -v "https://dns.xdp.es/dns-query?dns=AAABAAABAAAAAAAAA3d3dwZnb29nbGUDY29tAAABAAE" -H "accept: application/dns-message"
